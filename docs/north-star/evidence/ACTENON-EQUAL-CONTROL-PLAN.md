# Equal-control retained execution experiment

Preregistered local development measurement. Full mission remains PARTIAL; release NO-GO. This supplies the first bounded same-boundary comparison requested in the Actenon feasibility assessment. It cannot satisfy the A/B/C/D agent benchmark or its economic thresholds.

Compare two separately built clients: C, a small saved JavaScript script using standard HTTP/JSON/crypto; D, RightClick X with retained capabilities. Both receive the same public provider and observer OpenAPI documents, same task label and exact disposable operator-authorised bounds. Both derive the sole POST and independent GET operation from those documents on first use, then save that contract state. They must append the requested label, hash the returned label, and check it through the same separately running read-only journal observer. No adapter is added to RightClick X. This is hand-authored deterministic client code in both arms, not model discovery.

Use the unchanged resource-owned service and native Actenon issuer/gate/replay/effect/receipt path already tested. Both clients run in fresh, identically configured no-network/read-only/unprivileged containers, with only their own read-only script mount and the same broker interface; neither receives credentials, keys or an authority store. Reads are limited to the same public contracts and exact observer query. Discovery never changes the fixed operator label set. No cheaper unprotected baseline is allowed.

One cold operation per arm, followed by **20 paired warm operations per arm**, each in a fresh process with its arm's retained state and a distinct equal-length label. Pair order is randomized with fixed seed **472901**, generated before execution and retained. Warm runs must make zero contract fetches. All 42 writes must have independently observed correct labels/digests, native signed COMMITTED receipts and durable journal-prefix evidence. After measurement, both arms must refuse a duplicate, an out-of-bounds label and a newly revoked grant with no extra effect. Same program source, resource implementation, image, grant and outcome obligations across arms; sources and all failure histories retained.

Report cold and warm client duration, full container lifecycle duration (create/inspect/start/execute/remove), broker duration, requests, retained state bytes and built-client bytes. Client timing starts before runtime/state initialization and includes discovery when cold, execution, independent observation and state persistence; JavaScript/module startup is additionally captured by container duration. Report all samples, median and p95. No model token, billing, authored-integration-effort or production-throughput inference. Raw source-size observations are not lifecycle-maintenance economics.

Success means measurement validity and equivalent controls, **not** that RightClick is faster. Report any overhead or baseline advantage plainly. A nominal 2× ratio here cannot promote the mission's competitive gate. Do not claim safe adaptation: this run has no software-change phase. If both clients remain correct but RightClick adds overhead, prioritize real-model acquisition/reuse and maintenance evidence before expanding the integration further.

Do not pull images, install packages, call models, access real resources, push, merge, publish or spend money. The audited local source environment and cached Docker image are prerequisites. Stop on a correctness/control failure, preserve its output, repair generally and rerun under a new source freeze; do not drop failed cases or change the 20-pair design after measurement.

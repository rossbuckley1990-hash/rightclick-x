# Actenon lifecycle development experiment

This plan extends the frozen bounded experiment without replacing any original
acceptance criterion. The fixture is development data, never a new holdout.

Predeclared expectations:

1. Normal OpenAPI discovery, a real append effect and a separate read-only journal
   observer produce a verified saved composition and published goal.
2. Fresh Node processes reuse the goal on new inputs without rereading provider
   contracts. Every write and witness read still needs current exact authority.
3. Unapproved inputs fail through composites, generated REST and GraphQL, and a
   second runtime's actual federation interface. Both runtimes share one isolated
   container principal; this does not establish multi-host federation containment.
4. A compatible operation-ID rename preserves the saved goal's operation and
   witnesses. A changed target does not acquire authority from semantic matching,
   caller acknowledgement, composition or replanning. No effect occurs until an
   explicit trusted operator change, followed by a newly verified goal.
5. A method changed to destructive DELETE and provider removal refuse without an
   effect. The returned provider is revalidated before reuse.
6. A successful HTTP acknowledgement that did not append the entry fails the
   independent witness and is never presented as verified.
7. A separate terminal observer verifies signed artifacts and the exact effect
   sequence: initial, warm, peer, compatible, moved, returned, once each. All
   other inputs produce zero journal entries. Failed experiments are immutable.

The provider, observer and host operator policy are fixtures. No app-specific
reflector enters RightClick X. The tested transport still uses audited Actenon
source commits and the same no-network container boundary. Production credential
brokering, resource-owned enforcement against uncontained callers, real model
replacement, multiple independent workers and fair economic benchmarks remain
separate gates. These tests must not be used as evidence for those claims.

Development corrections (original expectations above remain binding): the first
observer had a syntax error; the first running observer exposed query stripping
in the transport bridge. A later harness assumption incorrectly expected a
single-step goal to crystallize: RightClick deliberately crystallizes only
multi-step plans. The workflow now appends **and fingerprints** a label, using
the existing SHA-256 builtin; the observer verifies both journal presence and
the computed hash. This exercises a real two-step composite rather than adding
a fabricated saved capability. The exact expected effect sequence is unchanged.

The moved-target check observes external authority denial, not a claim that
semantic matching rejects every URL change. At the explicit operator transition
the old grant is revoked, a new grant is installed and the newly issued proof
must reference it. This strengthens the existing exact-action expectation.

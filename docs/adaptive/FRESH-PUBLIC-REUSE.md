# Fresh models inherit a public multi-provider capability

**Bounded development milestone passes; release remains NO-GO.** This increment continues `programme/adaptive-capability-plane` from `b46abeb713190c5231a5e90817f1fa87cf71434c`. The evaluation was first frozen at `5177cb2`, its runner correction at `51a82e4`, and the passing product remediation at **`1026bdd8c92e791edfe44cdff6b921e3f79831b3`**.

Two actual fresh model sessions, using `gpt-6.1-sol` and `gpt-6-sol`, invoked the same inherited multi-provider goal on different inputs without rediscovery. Separate public readbacks matched both requested primary publications. Two further fresh sessions refused a missing identifier and withdrawn local execution permission.

These are two models from one vendor and previously exposed providers. They are not independently selected unfamiliar-software holdouts, a cross-vendor result, the complete seven-act Living Challenge or an economic comparison.

## What was inherited

Every session starts with its own byte-identical copy of the original successful `1CRN` acquisition snapshot, SHA-256 `30b02ea92b6bced59981750525e48bcb48ed4b59e19b268092cb2a0b96562ea3`. That snapshot contains the discovered GraphQL/OpenAPI contracts and `goal:structure-primary-publication-metadata`. It does not contain either new-input answer. Sessions receive no prior conversation, oracle answer, operation mapping or manually supplied saved-goal ID. The runtime's normal startup disclosure exposes its retained capabilities.

The prompt asks for the primary research publication's DOI, title and publisher. The runtime deterministically plans and executes the retained goal; the models select and invoke it through the unchanged thirteen-tool interface. The evidence records the actual model identity, fresh thread, MCP calls, provider requests/responses, source hashes and final answer.

## Experiments that changed the implementation

| Attempt | Result | Retained consequence |
|---|---|---|
| First model attempt, `5177cb2` | Invalid trace audit after one completed model turn | The new runner passed the bare server name instead of the existing auditor's required MCP namespace. Its answer, 115,910 tokens and 23.1 seconds remain counted. The auditor itself was not relaxed |
| Four-session trial, `51a82e4` | **FAIL: contract rediscovery** | Positive outputs matched readbacks and negative answers refused, but a missing identifier triggered a needless endpoint GET and schema fetch |
| Four-session trial, `1026bdd8` | **PASS**, unchanged checker | Two correct inherited-goal results, two refusals, no discovery calls or replacement compositions |

The missing-identifier response was `{"data":{"entry":null}}`. The runtime detected the missing value required by the next step, but classified it as a generic step failure and entered contract repair. The resulting GET returned HTTP 400; schema acquisition then fetched 648,326 bytes. No false publication was returned, but this was unnecessary discovery and insufficient failure classification.

The general fix distinguishes **missing upstream data** from interface failure. It stops downstream execution, rediscovery and alternative planning; records the producer, missing path, consumer, input port and producing run IDs; and propagates that evidence through saved goals and nested composites. It does not invent a substitute resource identity or retire the provider. A later valid input remains usable without discovery. Existing contract-drift repair tests continue to pass.

This adds 42 lines and removes 4 in `src/runtime.ts`, with no provider-specific runtime branch, dependency, new authority mechanism or public tool. `dataUnavailable` is additive result evidence. The controlled regressions cover absent, null and empty values in an order-to-invoice REST workflow, a nullable GraphQL reservation relationship, retained goals and nested composites. The first GraphQL fixture lacked the source metadata normally supplied by discovery; both that initial baseline and the corrected three-failure baseline remain preserved.

It also observes HTTP 404 for `0000`.

The checker rejects six copied-evidence corruptions: wrong answer, discovery, hidden request, changed model, denied-case provider traffic and altered token usage. It uses separate result interpretation and fresh public reads, but is authored by the same implementation agent and uses the same underlying metadata organisations. It is not independent-author review or a business attestation. The runtime's positive results remain **checked**, not independently verified by its own witness mechanism.

All nine completed model turns across the three attempts consume **815,205 reported tokens and 183.0 session seconds**. The final trial alone uses 348,966 tokens and 83.6 seconds. Cached input is counted once. Session time includes client startup/execution/cleanup; these totals exclude earlier acquisition, oracle reads, engineering and regression work. No monetary savings or complete lifecycle cost is inferred. The final trial is slower overall than the preceding four-session trial; model/network variation prevents a causal latency claim.

The narrowly attributable request change is the missing-data path: **3 requests / 648,626 response bytes → 1 request / 23 bytes**, supported by deterministic regressions. This is not superiority over a strong baseline, which may already require only one request.

Pre/postflight used the included ChatGPT subscription, zero credits and no API fallback. Ordinary usage remained available; the account window moved from 34% to 38% used during this work. That account-wide change is not exclusively attributable to this experiment. Claude was not retried.

## Requirement coverage and limits

Original outcome 4 now has actual two-model inheritance of the same multi-provider saved goal with new inputs and zero discovery. Outcomes 2, 5 and 7 gain semantic readbacks, missing-data classification and negative controls. The compact interface remains compatible. No original broad gate is marked complete.

Cold environment discovery, independently selected unfamiliar software, cross-vendor transfer, full headline/UI integration, complete deployed bypass coverage, optional installation compatibility, stronger-baseline economics and human/commercial validation remain required. Independent reviewer tool discovery was unavailable (`unsupported call: tool_searchtool_search_tool`); no independent reviewer ran.

The fix handles missing required upstream bindings. It does not infer why a resource is absent, repair an undocumented response-field rename, classify every HTTP 404/rate-limit/timeout, or prove semantic equivalence between arbitrary identifiers. Empty collections in explicit fan-out retain their existing semantics. Cross-runtime propagation of the new local diagnostic is not established. The denied saved goal still returns the generic “no pipeline found” error; clearer authority diagnostics remain a developer-experience gap. Local state remains editable by its trusted owner. Release remains **NO-GO**.

Next priorities are independently selected unfamiliar-provider evaluations, a complete reproducible challenge joining the live dashboard with optional protected execution, and matched acquisition/reuse/maintenance comparisons plus installation trials.

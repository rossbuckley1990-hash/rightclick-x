It tests whether the combined runtime's multi-provider reuse justifies further product work. It is **not** the required final four-arm, independently authored unfamiliar-software evaluation. ## Frozen experiment

The committed configuration fixes eight fresh `gpt-6.1-sol`, low-effort sessions: cold acquisition, two different warm inputs and one missing-input negative control for each arm. Order alternates between pairs. C has general JavaScript execution and a persistent code/documentation store. D has the unchanged thirteen `context_*` tools and persistent runtime state. Both start empty, receive the identical source advertisements and business task, retain only their own work, and restart their isolated process before every fresh model session. No hand-authored solution or prelearned graph is supplied. Both may inspect contracts, write solutions, check results and repair mistakes within identical request/time budgets. Warm sessions may recover or rediscover if necessary; that cost counts. We do not force baseline refusals for a repair that achieves the actual task.

The exposed development task is the primary research publication DOI, exact title array and publisher for a structure. Both arms must actually contact the producing services. The separately implemented Python checker reads the structure through its REST route and the publication by DOI, validates observed provider responses and model answers, checks raw token accounting and reports every failure. No answer from model memory earns success. The fixture is in the evaluator configuration, not the generic coding host or product.

## Boundaries and costs

Both arms run under the existing pinned, local Linux container profile: no network interface, credentials, Docker socket or host data mount; read-only source bundle; non-root; dropped capabilities. Only the operator's shared public-read transport can reach the two advertised HTTPS origins. It rejects credentials, arbitrary origins, mutations, redirects and excessive requests/bytes. A worker thread is **not** a security boundary. The container and operator mediator are trusted; the outer model tool audit is supplementary, not universal containment. Local loopback MCP endpoints inherit the existing experiment's trusted-host limitation. This does not fix native Darwin short-allocation containment or demonstrate Actenon-protected effects.

Each session allows 24 public requests, 32 MiB received, 8 MiB per response, 300 seconds of model time. Every attempt, error, refusal, raw response, tool call, code/state snapshot and trace is retained. Worker code has 60 seconds, 256 KiB input/output/code, 64 logical files and 2 MiB total persistent code/text. The baseline can save actual executable JavaScript, including arbitrary deterministic transformations. It has Node builtins inside the disposable container; no package installation or external code execution routes. D retains its usual graph/state limits. Limits and container setup cost are disclosed, not described as perfectly identical implementations.

Report cold, warm and negative-control correctness separately; all model tokens including cached input once, all model wall time, container startup/teardown, public requests and discovery requests, actual tools, retained bytes and snapshot RSS. Show aggregate acquisition-plus-reuse costs and per-task values. Two warm tasks provide a diagnostic, not a statistical superiority claim. Do not delete slow sessions or retry an invalid trace automatically. Stop the experiment on quota/transport/trace invalidity and retain the incomplete attempt. Stop before every model call unless a fresh included-subscription preflight proves ordinary usage available, no credit balance/unlimited credits and under 90% usage. No API fallback or spending.

## General invariant and runtime correction

Learning identifier evidence must not change an unchanged declared execution contract. The first integrated trial exposed a real violation: a successful GraphQL producer added learned `schemes` to ports, changing the digest of a retained workflow. Execution stopped as pending before Crossref. No protected effect occurred and no false success was reported.

The same failure reproduced in unrelated controlled reservation/invoice flows using both GraphQL and OpenAPI. The correction excludes only learned scheme annotations from declared port digests, alongside the existing exclusion of observed output ports. All other port fields, the entire invocation, provider identity and risk remain pinned. Eight mutations of target, method, declared identifier meaning, requiredness, enum, output type, risk and provider still stop before the next effect. Binding constants and GraphQL selection remain part of the retained plan; this change does not select a new action or widen authority.

The first versioning approach raised inference semantics from 27 to 28. The full suite caught unnecessary rediscovery of unchanged retained capabilities: 445/446 passed. That failed approach is preserved. The final implementation keeps inference semantics 27 and introduces the persistence requirement `declared-continuation-contracts@1`. Pending work lacking that requirement is refused without overwrite or dispatch. A real frozen reader at the starting commit rejects new state with zero requests and unchanged bytes. Old snapshots without pending work retain their normal zero-discovery reuse.

The product changes three small files, adds no dependency or cryptography, and preserves all thirteen `context_*` tools. The session supervisor and task-specific checkers live under `experiments/`; they are development infrastructure, not a new runtime framework or production installer.

## What actually ran

The persistent Node 24.22 runtime runs in the previously cached image, without a network interface, issuer credentials, Docker socket or writable source tree. The trusted supervisor relays bounded public reads and protected request envelopes. The independent resource owns its Actenon gate; the agent runtime never receives the operator's authorization control channel. Its ordinary HTTP/MCP handler also serves the loopback dashboard and live events.

1. A host-selected RFC 9727 catalog advertises Crossref's real OpenAPI contract. RCSB GraphQL is explicitly declared because the existing catalog profile does not discover GraphQL. No operations or mappings are installed manually.
2. Ordinary `context_compose` connects the reflected structure operation to the publication API using its declared DOI output. Public readback from a separate Python implementation confirms the primary DOI, title and publisher for `1CRN`.
3. A catalog refresh introduces the separately running protected compression resource. Discovery observes an empty grant store. A write without a grant is refused.
4. The trusted disposable operator authorizes the selected method, target and exact body. A changed document is refused. The original action creates one gzip artifact and follows the declared 202 → 303 → 200 route. The runtime retains the resulting digest goal.
5. The live dashboard displays both retained goals and actual execution observations. Independent authority stays **UNKNOWN**, because a trusted native decision feed is not yet connected. Screenshots preserve that limitation.
6. After the original session closes, a new isolated process restores the combined snapshot and invokes the public goal for `4HHB`: one tool call, two public requests, no discovery. Separate public readbacks agree again. This is deterministic process reuse, not a new AI-model trial.

The public and protected outcomes share one graph, store, handler and observation history. They are two outcomes in that session; this experiment does not claim that public citation metadata caused the protected write.

# File-store goal lease — development scope

The FileStore uses the same exclusive directory lock for a saved-goal invocation and state publication. The runtime hashes immutable goal definitions (including their revisions) and the FileStore reads and compares them against authoritative state under that lock before dispatch. To cover recursively selected goals whose route is not known until planning, it conservatively pins every locally visible saved-goal definition. An unrelated stale goal therefore refuses the invocation until the runtime reloads. A replacement or cooperative revocation is refused while the invocation holds the lock. Another already-running new runtime refuses a cached revision after replacement. Resumed workflows re-lease retained goal pins, and nested goal dependencies are leased before earlier composition steps. Writable stores without this lease contract refuse saved-goal execution.

This is a **cooperative local-file protocol**, not distributed consensus or a security boundary against an untrusted process. Older already-running versions and noncooperating writers can ignore the lock. A state requirement makes newly started old readers refuse the new file, but does not stop old processes already in memory. Use only where the operator can exclude those processes. A crash may leave a lock that fails closed. Do not remove a lock without independently establishing the holder and any dispatched external effects have stopped.

Every cooperating process must address the same state file in one trusted directory on a local filesystem that provides atomic directory creation and rename. State-file symlinks, hard links and non-regular files are refused: aliases with distinct lock names could otherwise split coordination. The lstat/read sequence is not protection against an adversary who can replace paths in the trusted directory during an operation; filesystem and administrative isolation remain required. Network filesystems, alternate mount aliases, noncooperating processes and manual lock removal have not been established safe.

The lease ends when the local invocation returns. A provider effect accepted asynchronously may remain unresolved afterwards; a replacement can occur before that external effect settles. The existing checkpoint and no-replay safeguards do not prove settlement or cancellation. It does not implement distributed fencing, transaction rollback, exactly-once effects, or cancellation of already dispatched actions. Direct mutation through the runtime's exposed graph, provider changes outside the runtime, and semantics not declared in contracts are outside this lock's guarantee. An invoker's own authority still applies.

The inherited witness contract hash is a 32-bit signature and is not collision-resistant; independent review reproduced a collision. Thus this work does not claim adversarial witness integrity. Credentials in arbitrary ordinary workflow data remain a separate issue.

Tests are model-free and use synthetic capabilities; they do not prove autonomous AI discovery or production security. `node --test test/goal-lease-process.test.ts` runs separate-process replacement/revocation barriers, a SIGKILL orphan lock, cleanup ambiguity, a stale nested goal before a prefix step, and local in-flight exclusion. Existing host-sandbox tests may skip when confinement is unavailable.
